UI/UX rethink — proposal

Five changes, one screen each: one navigation column, tabs that hold splits (the + splits instead of adding a tab, newest tab on the left), Jira keys linked everywhere, and a 13px type scale with 4px-grid spacing. Today/Yesterday/This week grouping stays exactly as it is — it's what works.

A · The Sessions screen, after

Everything you navigate to is in one block at the top-left. Tabs are your working set of sessions; each tab owns its own splits. The selected session's ticket is in the title bar.

C · Tabs and splits

The model every terminal you've used (iTerm2, Ghostty, Warp, WezTerm) teaches: a window has tabs, a tab has panes. Today a pane has tabs instead, so "+ Shell" lands as another tab in the same strip rather than beside Claude.

New tab goes to the left edge, beside the +. The strip reads newest → oldest, like the sidebar's Today list. Old tabs fall off the right end, which is where overflow already hides them. ⌘1 is always "the one I just opened".

Trade-off: no terminal I checked (iTerm2, Ghostty, Warp, VS Code) does this. They insert after the current tab, because newest-left shifts every tab's position and its ⌘-number on each open. So it becomes a setting, New tabs: left edge | after current, defaulting to left as you asked.

What changes underneath

The pane algebra in lib/panes.ts (grid, split, seams, drop zones) stays as is; it just moves from one global layout to one layout per session tab. Pane tab strips go away — a pane gets a 28px header (tool, cwd, ×) instead.

Dragging a pane header onto another pane's edge still re-splits; dragging a sidebar row onto a pane edge still puts another session beside this one ("compare two sessions").

Tab order: splice(at === -1 ? length : at) → insert at 0 in addToPane; one place, every opener goes through it.

E · Type, spacing, shape

The chrome is currently 11.5px rows with 9.5px metadata on 26px rows — denser than Linear, VS Code or Zed, and at 9.5px the metadata is hard to read on a non-Retina display. Proposal: one step up everywhere, on a 4px grid.

Fonts. Chrome stays on the system font (SF Pro on macOS, Segoe UI on Windows) — native beats bundled for a desktop app. The terminal is the one place a bundled font pays: today it asks for Cascadia Code → Consolas, neither of which is installed on this Mac, so it falls through to WebKit's generic monospace. Proposal: bundle JetBrains Mono (OFL), list ui-monospace, SF Mono, Menlo as fallbacks, and make family/size a Settings field.

Color. Unchanged, with one addition: Jira blue #4c9aff as a link color only — never a status, so it can't collide with the reserved success/warning/attention/destructive set.

Rollout order

1. Quick fixes — new tabs at the left; "+ Shell" splits beside instead of adding a tab. Small diffs in addToPane and PaneSessionMenu.
2. Navigation — one block in the sidebar, breadcrumb + usage in the title bar, ⌘1–4.
3. Jira links — detector + chips + terminal/transcript links with just a URL; then the hover card and "start from ticket" once a token is set.
4. Type scale — tokens in globals.css, then a sweep of the hardcoded text-[11.5px]/text-[9.5px] literals.
5. Tabs own their splits — per-session layout; the biggest change, last, once 1–4 have settled.
