Git — three directions

A session runs in a folder; if that folder is a git repo, the app can say which branch it's on, whether it's dirty, and what Claude changed — without you typing git status in a split. The three directions are layers, not rivals: A is the ambient minimum, B adds a place to look at changes, C is a project-level view. Each can ship on its own.

Read-only throughout: the app shows git, it doesn't commit, push or switch branches for you — that stays Claude's (or your shell's) job. Colors for git marks are deliberately not the session status colors (green/yellow/orange/red stay reserved): cyan for added, link-blue for modified, a muted red-grey for deleted. All data is made up.

A · Ambient: branch everywhere you already look

The branch and a dirty mark ride on things that already exist: the session row's second line, the title bar breadcrumb, and the file explorer, which gains M/A/D marks like any editor. Ahead/behind only when non-zero. Nothing new to open.

Good at

  • Zero new UI to learn; answers "which branch is this session on?" at a glance.
  • Catches the classic mistake — two sessions on the same repo, one on the wrong branch.
  • Cheapest to build: one git status --porcelain=v2 --branch per folder.

Weaker at

  • Says that something changed, not what.
  • One more token on an already-dense second line (compact list hides it).

B · Changes panel: what did Claude touch?

A right-edge panel beside the session (where the file explorer docks today), switchable Files / Changes. Changes lists modified files with a diff stat; selecting one shows the diff inline, a click opens it in the editor split. The tab carries the session's total +/−. "Since session start" scopes it to this session's work, not whatever was already dirty.

C · Project page: branches and worktrees ↔ sessions

The project page (going into a project in the sidebar) gains a git section. Its point is the mapping: which session works on which branch or worktree, what's dirty, what's ahead of the remote — and the last commits, so "what did we ship today" has an answer. Parallel Claude sessions in separate worktrees are where this pays off.

How it would work underneath. One git status --porcelain=v2 --branch -z (+ git diff --numstat for +/−) per folder, not per session, run by the Rust backend. Refreshed when a Claude session goes idle (the Stop hook we already receive), when you focus the window, and on a slow timer — never per keystroke. Folders that aren't repos cost one failed call, cached. No git binary → the feature quietly isn't there. Read-only: no commits, pushes or checkouts from the app.
